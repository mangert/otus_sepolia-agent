# Read-only инструменты Sepolia

Агент использует девять узких инструментов для чтения публичных данных Ethereum Sepolia.
Каждый инструмент перед основным запросом проверяет через `eth_chainId`, что RPC подключён к
Sepolia с chain ID `11155111`. Инструменты не создают подписи, не используют кошелёк и не
отправляют транзакции.

Все большие целые значения возвращаются десятичными строками, чтобы не терять точность при
JSON-сериализации. Пользовательские адреса валидируются и возвращаются в checksum-формате.

| Инструмент                | Назначение                                  | Основной JSON-RPC метод                         |
| ------------------------- | ------------------------------------------- | ----------------------------------------------- |
| `get_chain_info`          | Проверка сети и актуального блока           | `eth_chainId`, `eth_blockNumber`                |
| `get_native_balance`      | Нативный баланс Sepolia ETH                 | `eth_getBalance`                                |
| `get_erc20_balance`       | Баланс стандартного ERC-20 токена           | `eth_call`                                      |
| `get_block`               | Сводка блока                                | `eth_getBlockByNumber` или `eth_getBlockByHash` |
| `get_transaction`         | Данные транзакции                           | `eth_getTransactionByHash`                      |
| `get_transaction_receipt` | Receipt и статус выполнения                 | `eth_getTransactionReceipt`                     |
| `get_contract_code`       | Bytecode по адресу                          | `eth_getCode`                                   |
| `get_logs`                | Логи контракта в ограниченном диапазоне     | `eth_getLogs`                                   |
| `read_contract`           | Вызов одной функции контракта `view`/`pure` | `eth_call`                                      |

Если инструменту нужен актуальный блок, он сначала получает конкретный номер через
`eth_blockNumber`, а затем выполняет чтение на этом блоке. Это позволяет вернуть проверяемый
номер блока вместо неоднозначного `latest`.

## `get_chain_info`

Возвращает проверенную информацию о подключении к Sepolia.

- Вход: отсутствует.
- Результат: имя сети, chain ID, признак testnet, актуальный номер блока и признак read-only
  подключения.
- RPC: `eth_chainId`, затем `eth_blockNumber`.
- Ошибки: неправильная сеть, RPC-ошибка или некорректный номер блока.

## `get_native_balance`

Читает нативный баланс адреса в Sepolia ETH.

- Вход: `address` и необязательный неотрицательный `blockNumber`.
- Результат: checksum-адрес, конкретный номер блока, точный `balanceWei` и форматированный
  `balanceEth`.
- RPC: при необходимости `eth_blockNumber`, затем `eth_getBalance`.
- Ошибки: неправильный адрес или блок, неправильная сеть, невозможность определить актуальный
  блок, RPC-ошибка или отрицательный/некорректный баланс.

`get_native_balance` предназначен только для ETH. Балансы ERC-20 через него не читаются.

## `get_erc20_balance`

Читает баланс стандартного ERC-20 токена без ABI от пользователя. В инструмент встроены только
read-only функции `balanceOf(address)`, `decimals()` и `symbol()`.

- Вход: `tokenAddress`, `ownerAddress` и необязательный неотрицательный `blockNumber`.
- Результат: checksum-адреса контракта и владельца, конкретный блок, точный `balanceRaw`, а при
  доступных метаданных — `decimals`, `symbol` и `balanceFormatted`.
- RPC: при необходимости `eth_blockNumber`, затем три `eth_call` на одном блоке.
- Ограничения метаданных: `decimals` должен находиться в диапазоне от 0 до 255; `symbol` должен
  содержать от 1 до 32 безопасных буквенно-цифровых символов, точек, дефисов или подчёркиваний.
- Ошибки: неправильные адреса или блок, неправильная сеть, ошибка `balanceOf` или некорректный
  сырой баланс. Ошибки `decimals()` и `symbol()` не скрывают успешно прочитанный сырой баланс, а
  возвращаются в `metadataWarnings`.

Символ вроде `USDC` не считается идентификатором контракта: в тестовой сети несколько контрактов
могут вернуть одинаковый символ.

## `get_block`

Возвращает ограниченную сводку блока без полных объектов транзакций.

- Вход: `identifier` — `latest`, неотрицательный номер блока или 32-байтовый hash;
  `maxTransactionHashes` — необязательный лимит хэшей транзакций.
- Результат: номер, hash, parent hash, Unix timestamp в секундах, `timestampIso`, miner, gas limit,
  gas used, base fee, количество транзакций и ограниченный список их хэшей.
- RPC: `eth_getBlockByNumber` или `eth_getBlockByHash` с отключёнными полными объектами
  транзакций.
- Лимиты: по умолчанию возвращается до 20 хэшей, допустимо от 0 до 100. Поле
  `transactionsTruncated` сообщает об усечении.
- Ошибки: некорректный идентификатор или лимит, неправильная сеть, отсутствующий блок,
  RPC-ошибка или malformed-ответ. `timestampIso` равен `null`, если timestamp выходит за диапазон
  JavaScript `Date`.

## `get_transaction`

Возвращает основные поля транзакции без потери числовой точности.

- Вход: 32-байтовый `hash` транзакции.
- Результат: hash, статус `confirmed` или `pending`, данные блока, `from`, `to`, value в wei,
  nonce, gas limit, fee-поля в wei per gas, input и тип транзакции.
- RPC: `eth_getTransactionByHash`.
- Ошибки: неправильный hash или сеть, отсутствующая транзакция, RPC-ошибка, malformed-ответ либо
  несовпадение хэша в ответе с запрошенным.

У pending-транзакции `blockHash`, `blockNumber` и `transactionIndex` равны `null`; инструмент не
придумывает статус выполнения или подтверждения.

## `get_transaction_receipt`

Возвращает receipt и подтверждённый статус выполнения транзакции.

- Вход: 32-байтовый `hash`; необязательный `maxLogSummaries`.
- Результат: статус `success` или `reverted`, данные блока и транзакции, адрес созданного
  контракта, gas usage, effective gas price и ограниченная сводка логов.
- RPC: `eth_getTransactionReceipt`.
- Лимиты: по умолчанию до 20 сводок логов, допустимо от 0 до 100. Поле `logs.truncated` сообщает
  об усечении, а `logs.count` сохраняет полное количество.
- Ошибки: неправильный hash или лимит, неправильная сеть, отсутствующий receipt, RPC-ошибка,
  malformed-ответ либо несовпадение transaction hash.

## `get_contract_code`

Проверяет bytecode адреса на конкретном блоке и возвращает ограниченное preview.

- Вход: `address`, необязательный `blockNumber` и необязательный `maxPreviewBytes`.
- Результат: checksum-адрес, конкретный блок, `isContract`, полный размер bytecode, keccak256 hash,
  preview и признак усечения.
- RPC: при необходимости `eth_blockNumber`, затем `eth_getCode`.
- Лимиты: preview по умолчанию 256 байт, допустимо от 0 до 4096 байт.
- Ошибки: неправильный адрес, блок или лимит, неправильная сеть, RPC-ошибка или некорректные hex
  данные.

Пустой код `0x` означает `isContract: false`; `bytecodeHash` в этом случае равен `null`.

## `get_logs`

Читает логи одного контракта в явном ограниченном диапазоне блоков.

- Вход: `address`, включительные `fromBlock` и `toBlock`, а также необязательные `topics`,
  `maxBlockRange`, `maxResults` и `maxDataPreviewBytes`.
- Результат: фактический диапазон и его размер, полное количество совпавших логов, ограниченный
  список логов и признак усечения. Для каждого лога возвращаются блок, транзакция, индекс, topics,
  размер data и ограниченное preview.
- RPC: `eth_getLogs`.
- Лимит диапазона: по умолчанию 2000 блоков, максимум 10000.
- Лимит результата: по умолчанию 20 логов, максимум 100; один RPC-ответ не может содержать более
  10000 логов.
- Лимит data preview: по умолчанию 256 байт, максимум 4096.
- Topics: не более четырёх позиций; каждая позиция принимает один hash, `null` или OR-массив до
  20 хэшей.
- Ошибки: неправильный адрес, диапазон, topics или лимиты, неправильная сеть, RPC rate limit,
  RPC-ошибка либо malformed-ответ.

## `read_contract`

Вызывает одну явно выбранную функцию контракта с ABI пользователя.

- Вход: `address`, ABI, каноническая полная `functionSignature`, массив `args` и необязательный
  `blockNumber`.
- Результат: checksum-адрес, конкретный блок, каноническая сигнатура, mutability и
  JSON-совместимый результат. Значения `bigint` сериализуются без потери точности.
- RPC: при необходимости `eth_blockNumber`, затем `eth_call`.
- Read-only граница: разрешены только функции `view` и `pure`; `payable` и `nonpayable`
  отклоняются до RPC-вызова.
- Перегрузки: функция выбирается только по полной сигнатуре, например `balanceOf(address)`.
- Лимиты: до 1000 ABI-элементов, до 100 параметров функции, до 100 аргументов в tool schema;
  вложенность массивов аргументов — до 16, длина одного массива — до 1000 элементов.
- Ошибки: неправильный адрес, ABI, сигнатура, mutability, количество или тип аргументов, блок,
  неправильная сеть, revert/RPC-ошибка либо невозможность сериализовать ответ.

## Общие правила ошибок

Инструменты не переключают сеть или RPC-провайдера автоматически. Ошибки валидации происходят до
основного RPC-вызова. Сетевые ошибки, timeout, rate limit, revert, отсутствие объекта и
malformed-ответ передаются агенту с исходной причиной; секреты и URL с ключами очищаются перед
показом пользователю.
